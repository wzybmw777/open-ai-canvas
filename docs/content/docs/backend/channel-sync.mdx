# 上游渠道同步管理

后台「模型与资源 → 渠道同步」为每个系统渠道保存独立同步配置。定时任务由后端 Worker 执行，不依赖管理员保持登录或浏览器打开。时区固定为 `Asia/Shanghai`，每 30 分钟执行一次，在每小时整点和半点到期，Worker 每 15 秒领取到期任务；服务停止期间错过的任务在恢复后补执行一次，不逐次重放。

## 同步脚本

目前提供两个受管脚本适配器，管理端选择脚本并编辑其配置，不执行上传的 Shell 或任意命令：

- **授权目录监控**：使用渠道已保存的凭证读取 OpenAI 格式的 `/v1/models`，核对型号授权。适合免费渠道或上游未提供公开价格目录的情况。
- **模型广场价格同步**：同时读取授权目录和 HTTPS 公开 `model-plaza` JSON，按管理员选择的分组 ID 匹配上游 SKU、图片质量或视频清晰度。可同步非空简介，以及已配置且启用价格档的成本和售价。

配置中可选择是否导入新型号，导入时保持停用、不推断能力或接口协议。同步同时核对启用和停用的已有型号：有效价格档对应的上游 SKU 全部恢复授权与报价，且本地协议、能力和价格档完整时，自动重新启用，包括此前手动停用的型号；恢复时按原成本／售价比例更新价格。缺少任一有效 SKU 的授权或报价时停用相关本地型号。尚未配置完整的导入型号继续停用并提示完善配置；已删除或合并进模型家族的 SKU 不恢复或重复导入。停用或删除的渠道不领取定时任务。

「授权目录监控」没有公开价格源，只核对授权并要求本地价格、协议和能力完整；「模型广场价格同步」始终检查报价是否存在，关闭“同步成本与售价”仅停止改价，不跳过缺价停用和报价恢复启用。空值、未返回对应规格报价属于缺价；明确的零价是有效报价。网络失败、非法报价、计费单位变化或报价歧义仍报告失败并保留原配置。

同一上游型号拆为多个本地选项时，保留各选项已有的非空简介，避免把其他分辨率或时长限制写入当前选项；空简介仍从上游补齐，价格与授权检查照常同步。

所有渠道共用上游简介过滤：同步写入前移除人民币、美元等金额及其计费单位，保留时长、清晰度、参考图／视频／音频数量、速度和并发说明。该过滤同样适用于关闭“同步成本与售价”的任务；实际成本与售价仍由结构化价格档维护。本站已检查全部六个渠道的 22 个型号，清理火山 Seed Audio 与宇熙四个停用型号中残留的金额；未配置同步的渠道和停用型号也纳入存量简介清理。

## 管理操作与执行记录

模型成本取所选上游渠道分组中对应 SKU / 规格的 `pricing` 报价。`official_pricing`、其他分组价格和简介中的供应商直连价格均不作为该渠道成本；例如宇熙组 `seedance-2.0（YX）` 的分组报价为 0.35 元/秒时，成本为 350,000 微积分/秒，简介中的 0.25 元/秒不覆盖它。

- 保存配置后，启用的任务从下一个北京时间整点或半点开始执行；暂停会清除下一次自动执行时间，仍可手动「立即同步」。现有启用任务的较远执行时间会自动提前至下一个半小时；已经到期的任务不延后，正在执行的任务保留租约。
- 「立即同步」异步返回执行记录，页面轮询展示执行中、成功或失败；记录保留授权数量、新增／启用／停用型号、更新价格档与简介数量，以及警告或失败原因。
- 「授权」是上游目录返回的型号数量，不是本站已启用数量；「新增」是本次新增的本地记录数，「启用」与「停用」是本次状态变化数，「更新 0 个价格档」表示价格未变化。已停用型号在授权与报价恢复且本地配置完整后自动启用，重复同步不会重复计入启用数量。
- 模型广场价格分组不存在或为空时，视为同步成功但上游模型已下线；执行记录保持「成功」，并提示「上游价格分组不存在或为空，相关模型已停用」，同时在同一事务中停用该渠道当前已启用的模型。
- 单次同步最多执行 3 分钟，数据库领取租约为 5 分钟。手动与定时领取同一渠道互斥，多实例不会重复领取；执行时不能修改配置。
- 模型变更与成功记录在同一事务提交，校验渠道、模型和价格档的版本与更新时间；管理员并发修改时整批回滚。
- 过期租约会被恢复并标记中断；未完成的定时任务重新入队，成功任务不会因重启再执行。未知供应商错误不保存原始 URL、密钥或响应正文。

## 从宿主机 QT 定时器切换

启用后台管理的 QT 同步后，应停用旧的 `open-ai-canvas-qt-sync.timer`，避免两个机制同时改价。新的 Worker 按现有价格比例定价，不再强制使用旧脚本的 120% 成本加价规则；配置完整的已有型号随上游授权和报价自动启停。

```bash
sudo systemctl disable --now open-ai-canvas-qt-sync.timer
```

旧脚本仍可人工检查，但不要与后台任务并发执行。公开价格目录失效时，在执行记录中处理失败原因；不能改用生成请求探测模型，避免产生收费。
